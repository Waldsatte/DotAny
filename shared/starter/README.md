# DotAny Starter

The template a new DotAny program starts from: the family's window around an empty work area. It opens a `.txt` or
`.md` file, keeps its bytes, and saves them back atomically, so every part of a DotAny program that is not the program's
own work is already there and already working: the top bar, the file menu with recent files, drag and drop, Save As with
its size estimate, the unsaved-changes prompt, the settings panel with its languages and licence page, day and night
themes, and one file per window. It is a [Tauri 2](https://tauri.app) program: a page in `src/` (plain JavaScript, built
with esbuild) and a Rust program in `src-tauri/`. Nothing in it is meant to be shipped as it is.

## Formats

| Format | Opens | Can be saved as |
|---|---|---|
| TXT, Markdown | yes, as bytes | TXT, Markdown |

The starter does not interpret what it opens: a save is a faithful copy. A new program replaces this with its own
reading and writing.

## Starting a new tool from it

The steps for a tool called Recorder, at the top of the repository:

1. **Copy** `shared/starter` to `recorder/`, leaving out `node_modules`, `dist` and any test output.
2. **Point it at the shared code.** The starter sits two levels inside `shared/`; a tool at the top of the repository
   sits one level beside it.
   - `src-tauri/Cargo.toml`: `dotany-base = { path = "../../shared/rust" }`
   - `scripts/build.mjs`: `import { buildTool } from '../../shared/scripts/build.mjs';`
   - Imports in the page stay as they are: `@dotany/web/…` always means `shared/web`.
3. **Name it.** Replace every `Starter` and `starter`:
   - `package.json` `name`; `tauri.conf.json` `productName` and `identifier` (`com.dotany.recorder`); the package, lib
     and bin names in `Cargo.toml`, and the library's name in `main.rs`.
   - `src-tauri/src/app.rs`, the `Tool`: `name`, `folder`, `data_env` (the environment variable that moves the program's
     data folder), `user_dir` (`"Music"`, `"Pictures"`, `"Videos"` or `"Documents"`: where the dialogs start),
     `extensions` (the open dialog's filter and what can be opened at all) and `sniff` (a look at the bytes, or
     `any_bytes`).
   - `src/main.js`: `name`, `dropTitle` (the empty window's title), `fileKind` (the open dialog's filter name),
     `formats` and `formatOf` for the Save As card.
   - `scripts/build.mjs`: `name`, and `icons` (`file` for the recent-files rows, then the program's own buttons, by
     Lucide icon name).
   - `src-tauri/icons`: the starter's icons are placeholders.
   - `src-tauri/Info.plist` and `src-tauri/lproj/` are generated by `shared/scripts/mac-plist.mjs` from the installer's
     component list (`installer/payload.json`); register the new program there rather than editing them by hand.
4. **Make it read and write.** In `app.rs`, replace the `Doc` type, `open_file`, `estimate_save` and `save_file` with the
   program's own. Every open calls `dotany_base::opened_in`; every save writes with `dotany_base::atomic` and then calls
   `dotany_base::saved_in`. Add the commands to `dotany_base::handler![…]`. In `src/main.js` the `open`, `show`,
   `clear`, `dirty`, `discard`, `estimate`, `save` and `saved` hooks connect them to the shell; call `shell.changed()`
   after every edit, undo and redo.
5. **Draw the work** inside `shell.stage`. Floating parts go in with `shell.place(…)`, a side panel with
   `shell.sidePanel(id, icon, label)`, a top-bar button with `shell.headButton(…)`. Use `shared/web/parts.js` and the
   classes in `shared/web/family.css` before writing anything new. The program's own `src/styles.css` comes after the
   family's sheet and should only add to it, using the family's colour, motion and size variables.
6. **Words.** Chinese is the key of the language tables: every Chinese string the program adds gets its English in
   `src/lang/en.json`, and the other languages are the `src/lang/<code>.json` files, loaded when chosen. Fixed words in a
   part of the page that is built once go through `shell.translates(…)`; what is redrawn uses `shell.onLang(…)`.

## Building

From this folder, with Node.js and Rust stable (on Windows, the MSVC toolchain):

```powershell
npm ci
npx tauri build --no-bundle
```

This builds the page (`node scripts/build.mjs`, which writes `dist/`) and then the program, `dotany-starter.exe`, in the
`release` folder under Cargo's target folder (`CARGO_TARGET_DIR` if set, otherwise `src-tauri/target`). The page build is
the family's, `shared/scripts/build.mjs`; it also writes `src/icons.js` from `lucide-static`. `src/notices.generated.js`,
the licence notices the program shows, is written by `shared/scripts/notices.mjs`.

## Where things are

- `src/main.js`: the whole page, which is one `createShell` call with this program's hooks (`@dotany/web/shell.js`).
- `src/backend.js`: this program's own commands, next to the family's in `@dotany/web/backend.js`.
- `src/lang/`: the program's own words in the other languages; the family's are in `shared/web/lang`.
- `src/styles.css`: this program's own sheet, empty here.
- `src-tauri/src/app.rs`: the `Tool`, the open file of each window, and the three commands the page calls.
- `src-tauri/src/main.rs`, `lib.rs`: the entry point, which only calls `app::run`.
- `src-tauri/tauri.conf.json`, `capabilities/default.json`, `windows-app-manifest.xml`, `Info.plist`, `lproj/`: the
  window, the content-security policy, the permissions and the platform manifests.
- `shared/rust` (`dotany-base`) and `shared/web` (`@dotany/web`) are everything else.

## How it works

The page asks `createShell` for the family's window and fills in the hooks that say what is this program's own. A
window starts empty; opening a file calls `open_file`, which reads the bytes into that window's slot. Save As asks
`estimate_save` for the size shown on the card and then calls `save_file`, which writes to a temporary file in the target
folder and moves it into place, so a failed save never damages the file that was there. Each window keeps its own file
(`PerWindow`), so a command acts on the window that called it, and `forget` drops what a window held when its file is
closed or the window goes.

## What it is careful about

- **A save is atomic** (`dotany_base::atomic::atomic_write`), and a failure is reported with its kind (read-only folder,
  full disk, no permission) instead of a bare error.
- **One file per window.** No command assumes there is a single window called `main`.
- **A panic in an asynchronous command** fails that command and is written to the crash log; the release profile keeps
  `panic = "unwind"` for this.
- **A strict content-security policy**: the page loads only its own scripts, styles and fonts and talks only to the
  program's own commands.
- **A narrow set of permissions** (`capabilities/default.json`): the page may send and receive events and move the window
  by its top bar; everything else goes through the program's own commands.

## Windows and the Mac

It runs on Windows (on Microsoft Edge WebView2) and on Macs with Apple silicon. The platform-specific Rust is in
`dotany-base`; this folder holds only the manifests each platform needs (`windows-app-manifest.xml` marks the program as
Windows 10 and 11 aware, which the snap layouts over the maximize button require; `Info.plist` and the language folders
under `lproj/` describe the Mac application).
